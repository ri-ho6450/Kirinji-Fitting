# キリンジ｜Uniform Size Pro V2

制服販売店で、最初に試着するサイズの候補と理由を案内するReact / TypeScriptアプリです。最終サイズは実際の試着で決定してください。

## Windows：ダブルクリックで起動

1. 初回だけNode.js 24 LTSをインストールしてください。
2. ZIPを**すべて展開**し、フォルダ内の `Start-Kirinji.bat` をダブルクリックします。
3. 初回は依存関係を自動インストールします（インターネット接続が必要です）。準備完了後、既定ブラウザでアプリを開きます。

2回目以降も同じファイルをダブルクリックするだけです。ターミナルへのコマンド入力は不要です。起動ウィンドウは使用中開いたままにし、終了は `Ctrl+C` またはウィンドウを閉じてください。

アプリが既に同じフォルダから起動していれば、サーバーを重複起動せずブラウザを開きます。別のサーバーがポート3100を使用している場合は、エラーを表示します。ブラウザ保存データの場所が変わらないよう、ポートを自動変更しません。

Node.js未導入や起動失敗時は、メッセージを表示してウィンドウを残します。インストールした直後に起動できない場合は、フォルダを開き直して再実行してください。Windowsで実機のダブルクリック動作は未検証です。ランチャー本体はLinux環境で検証しています。

ポート3000を使うシフトアプリなどと同時に起動できます。URLは `http://localhost:3100` です。変更する場合は `scripts/app-config.mjs` の `appPort` を編集してください（手動起動・ランチャー共通）。

以前 `http://localhost:3000` で保存した寸法マスタは新ポートでは自動表示されません。必要な場合は旧アプリからマスタJSONをエクスポートし、新アプリへ読み込んでください。ポートごとにブラウザの保存領域が分かれます。

## 開発

Node.js 24、npm 11で動作確認済みです。APIキーや外部サービスは不要です。

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
```

開発サーバーはポート3100です。検証コマンド：

```sh
npm test
npm run lint
npm run build
```

`lint` はTypeScriptのstrict型チェックです。`package-lock.json`を依存関係の正本にします。

## 最初の登録

実在校の商品実寸を捏造しないため、初期のサイズマスタは空です。「学校別寸法表」で学校・商品を選択し、サイズを追加してください。初期商品一覧も登録用のひな形です。実際の取扱商品・性別・カテゴリーを確認してください。

「＋ この学校に商品を追加」で商品名・男女区分・カテゴリ・判定基準・メーカー・品番を登録できます。セーラー服・セーター以外も自由な商品名で登録できます。男女で実寸が異なる場合は必ず別の商品として登録してください。

取込データは男女区分を持ちます。CSVの「性別」列を男子・女子・男女共通で指定し、取込先区分と一致することを確認してください。性別列のない旧CSVは画面で選択した区分を使います。PDFの品名に男女が明記されている場合は取込区分に反映し、保存前に確認します。男女混在データや登録済み商品の性別変更は拒否します。

CSVまたはタブ区切りで取り込めます。例（テスト用で、実在商品の寸法ではありません）：

```csv
サイズ名,胸囲,肩幅,袖丈,着丈,呼称身長
160A,104,41.5,57,66,160
165A,107,42.5,59,68,165
170A,110,43.5,63,70,170
```

PDFのサイズが横並び・寸法項目が縦並びの表にも対応します。複数のサイズブロックを取り込み、「肩巾」を肩幅として扱います。

PDF抽出・CSV読込は仮データです。編集表で原本と照合し、確認チェック後に保存します。PDFは画像だけの資料や複雑な表では抽出できません。その場合は手入力してください。列名を推測したり「身幅」を胸囲へ自動換算したりしません。PDF表示・解析は判定エンジンから独立しています。PDFワーカーもアプリに同梱し、CDNを必要としません。

サイズには胸囲・ウエスト・ヒップ・肩幅・袖丈・着丈・股下・呼称身長・ウエスト調整差分を登録できます。スカートは「股下」ではなく「必要丈／製品丈」を評価します。入力が必須な寸法、HARD条件の製品寸法が欠けている場合は判定を止めます。

ウエスト調整は製品ウエストに対する差分です。70cm、調整最小-3、調整最大+3なら対応範囲は67～73cm。サイズ行の値を商品共通値より優先します。

## 判定ルール

- 商品名からカテゴリを推測しません。`Product.category`と`sizeRuleId`で分岐・参照します。
- 各部位の製品寸法－身体寸法を独立評価します。
- HARD条件違反は候補外。FitScoreは`null`で、平均点で補いません。
- 現在適応はHARD通過サイズの最高FitScore。同点では登録順序の小さいものを採用します。
- 初回試着候補は全評価部位が許容範囲内のものだけです。該当サイズがなければ、現在適応があっても初回試着推奨は出しません。
- 成長候補は現在Fit、設定された身長差範囲、実寸の余裕増加を確認します。単純な1サイズアップは行いません。
- 任意寸法の未評価部位は得点から除外し、評価済み部位の重みを再配分します。
- 比較候補は重複を除き最大3件。全サイズ一覧には候補外の理由も表示します。

すべての閾値は`src/data/fitRules.ts`の暫定値です。袖丈、丈、ヒップなど仕様に具体値がない部位も暫定としてここに集約しています。セーラー服・セーター・シャツ・体操服の上衣は上衣ルール、体操服の下衣はスラックスルールを暫定共有しています。製品に合わせて必ず検証・補正してください。「その他」カテゴリは専用ルールを登録するまで判定できません。

胸囲の連続境界は `<15` 小さい、`[15,20)` 小さめ、`[20,24)` 適正、`[24,28]` 推奨、`(28,32]` 大きめ、`>32` 大きすぎです。

`src/data/growthRules.ts`の初期成長ルールは、中学男子上衣の身長差10～15cm、中学女子上衣5～10cmの候補検索用です。AI成長予測ではありません。対応ルールや呼称身長がない場合は成長によるサイズアップを行いません。袖出し・裾出しは将来の対応量として別表示し、現在の袖丈不足を帳消しにしません。

管理画面のJSON編集で学校・商品・ルール・成長ルールを変更できます。参照整合性・数値範囲を検証し、確認後に保存します。閾値と重みの変更は必ず試着検証してください。

## 保存とバックアップ

確認済みマスタはブラウザのlocalStorage、PDF原本はIndexedDBに保存します。サーバー保存や端末間同期はありません。マスタJSONを書き出して保管してください。PDFはJSONバックアップに含まれません。原本ファイルも別途保管してください。

旧版`uniform_school_data`は変更しません。管理画面で旧データを書き出し、意味・カテゴリ・製品実寸を確認してV2へ登録してください。壊れた保存データを無断上書きしません。

採寸値はセッション中だけ保持します。「採寸・判定記録を書き出す」で体重を含む入力と結果をJSONとして保存できます。氏名を扱わず、試着・購入結果の将来拡張に使えるIDと結果型を分離しています。

## 構成

- `src/domain/types.ts`: マスタ・採寸・判定結果の型
- `src/data/`: 学校、商品、サイズ、Fit・成長ルール
- `src/logic/`: 入力検証、部位評価、FitScore、成長評価、推奨選定
- `src/components/`: 部位評価カード、構造化寸法表管理、PDF原本表示
- `src/utils/`: 保存、CSV読込、PDF抽出／原本保存
- `tests/fixtures.ts`: 指定ケース用データ（実運用マスタには未接続）
- `tests/engine.test.ts`: 指定6ケースおよび境界・不足・調整範囲・データ整合性テスト

実店舗の寸法表登録、暫定ルールの検証は運用開始前に必要です。写真採寸API、購入結果の保存、端末間同期、成長予測は今回の実装範囲に含めていません。
